# Сканер российских вин

Сервис принимает фотографию этикетки, выделяет бутылку, ищет товар в Qdrant
по SigLIP2 и, если доступен OCR, уточняет результат по тексту этикетки.

## Быстрый запуск

```bash
cp .env.example .env
docker compose up --build
```

Qdrant запускается с постоянным volume. Каталог и обученная YOLO-модель
передаются API-контейнеру из локальной папки `data/`.

Для запуска с NVIDIA GPU:

```bash
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up --build
```

На хосте должны быть установлены NVIDIA Container Toolkit и совместимый
драйвер. При `auto` PyTorch и YOLO выбирают CUDA, затем MPS, затем CPU.

## Индексация и расширение каталога

Каталог расширяется без удаления существующих точек. Новые изображения нужно
положить в `data/images/`, а актуальный JSON-каталог — в
`data/embedings/wine_catalog.json`, после чего запустить:

```bash
uv sync --extra ocr
uv run python src/scripts/index_catalog.py
```

Индексация идемпотентна и продолжает работу с уже загруженными файлами.
Для полной пересборки обеих коллекций используется `--rebuild`:

```bash
uv run python src/scripts/index_catalog.py --rebuild
```

Если OCR временно не нужен или не хватает памяти:

```bash
uv run python src/scripts/index_catalog.py --filenames-only
```

Скрипты используют `Slug` каталога даже тогда, когда имя файла изображения
не совпадает со slug. Для записи без эталонной фотографии создаётся OCR-точка
по профилю каталога.

## API

Обычный поиск:

```bash
curl -F "photo=@photo.jpg" http://localhost:8000/search
```

При найденном товаре ответ содержит `found=true`, список кандидатов,
`confidence`, визуальный `margin` и число подтверждённых OCR-совпадений.
При слабом совпадении сервис возвращает кандидатов как возможные аналоги,
но ставит `found=false` и не выдаёт их за точную карточку.

Кандидат с известным `slug` дополнительно обогащается полем `card` из
`APP_CATALOG_PATH`. В карточке доступны название, винодельня, регион, сорт,
категория, цвет, описание, рейтинг, гастрономические сочетания и ссылка на
страницу вина. Фронтенд показывает полную карточку при точном совпадении и
карточки похожих вин, если исходное вино не удалось уверенно определить.

Проверочный контракт кейса:

```bash
curl -F "image=@photo.jpg" http://localhost:8000/v1/eval/predict
```

Для уверенного результата endpoint возвращает плоский JSON:

```json
{"slug":"wine-slug"}
```

Для изображения вне каталога возвращается HTTP 404, чтобы evaluator не получил
случайный slug.

## Основные настройки

Все настройки имеют префикс `APP_` и могут быть заданы в `.env`:

- `APP_CATALOG_PATH` — путь к JSON-каталогу карточек вин;
- `APP_EMBEDDING_DEVICE=auto|cuda|mps|cpu`;
- `APP_YOLO_DEVICE=auto|0|cpu`;
- `APP_OCR_DEVICE=auto|gpu:0|cpu`;
- `APP_RETRIEVAL_MIN_CONFIDENCE` — порог принятия точного совпадения;
- `APP_RETRIEVAL_VISUAL_OCR_CONFIDENCE` — минимальная уверенность для
  визуального top-1, подтверждённого OCR;
- `APP_OCR_ENABLED` — включение дополнительного OCR-канала.

Confidence не является необработанным cosine-score: он объединяет визуальный
score, отрыв от второго кандидата и подтверждённые OCR-совпадения. Порог нужно
калибровать на размеченной полевой выборке.

## Ограничения

- официальный F1 нельзя получить без закрытой таблицы правильных slug;
- CPU-сборка PaddleOCR работает на CPU даже при наличии CUDA для PyTorch;
  SigLIP2 и YOLO при этом используют GPU;
- если в JSON-каталоге отсутствуют отдельные поля, соответствующие поля
  карточки не показываются.
