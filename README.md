# Сканер российских вин

Сервис принимает фотографию этикетки, выделяет бутылку, ищет товар в Qdrant
по SigLIP2 и, если доступен OCR, уточняет результат по тексту этикетки.

## Быстрый запуск

Production-образ собирается с GPU-версиями PyTorch/Paddle для CUDA 12.6 и не
зависит от конкретной модели видеокарты. На Docker-хосте должны быть
установлены совместимый NVIDIA-драйвер и NVIDIA Container Toolkit; сам образ
содержит CUDA runtime-библиотеки, но не драйвер хоста.

```bash
cp .env.example .env
docker compose up --build -d
```

Проверить доступность GPU до запуска API можно так:

```bash
docker run --rm --gpus all nvidia/cuda:12.6.0-base-ubuntu24.04 nvidia-smi
```

Если эта проверка завершается ошибкой `could not select device driver` или
`no known GPU vendor`, нужно настроить NVIDIA Container Toolkit на хосте.
CPU-only и AMD-хосты не могут использовать этот GPU-образ: для них нужен
отдельный CPU-профиль зависимостей, поскольку GPU-wheel Paddle требует
`libcuda.so.1` при импорте.

Все внешние веса (SigLIP2, multilingual MiniLM, PP-OCR и YOLO) скачиваются на
этапе `docker compose build api`. Во время запуска для Hugging Face включён
offline-режим, поэтому первый пользовательский запрос не скачивает модели из
сети. Датасеты и CLI-скрипты в образ не попадают; каталог и эталонные фото
остаются отдельным read-only bind mount `./data:/app/data:ro`.

Qdrant и PostgreSQL запускаются с постоянными volume. JSON-каталог и обученная
YOLO-модель передаются контейнеру из локальной папки `data/`. JSON используется
только как исходный файл импорта: рабочий API и индексаторы читают карточки,
описания, фотографии и ссылки исключительно из PostgreSQL.
При старте контейнера entrypoint выполняет миграции и импортирует JSON только
если таблица каталога пуста или в ней ещё нет ссылок.

PostgreSQL и Qdrant в этом Compose-файле доступны с хоста только через
`127.0.0.1`; API обращается к ним по внутренним именам сервисов. Для реального
production нужен HTTPS reverse proxy: браузер разрешает камеру только в secure
context (HTTPS или localhost), но загрузка готового файла от этого не зависит.

После первого запуска нужно один раз построить коллекции Qdrant из окружения,
где доступны CLI-скрипты и исходные изображения:

```bash
uv run --extra ocr python src/scripts/index_catalog.py
```

До завершения индексации endpoint поиска корректно отвечает сообщением о том,
что коллекции ещё не готовы. Индексацию не следует запускать в entrypoint API:
это тяжёлая одноразовая операция, а не часть каждого рестарта приложения.
Production-образ API намеренно не содержит CLI-скрипты индексации и обучения.

Схема PostgreSQL управляется Alembic. В Docker миграция `upgrade head`
запускается entrypoint перед стартом API. При локальном запуске сначала
выполните:

```bash
uv run alembic upgrade head
```

## Индексация и расширение каталога

Каталог расширяется без удаления существующих точек. Для первичной загрузки или
обновления каталога выполните импорт:

```bash
uv run python src/scripts/import_catalog.py
```

Новые изображения нужно положить в `data/images/`, а актуальный JSON-каталог —
в `data/embedings/wine_catalog.json`, после чего запустить:

```bash
uv sync --extra ocr
uv run python src/scripts/index_catalog.py
```

Индексация идемпотентна и продолжает работу с уже загруженными файлами.
Для полной пересборки обеих коллекций используется `--rebuild`:

```bash
uv run python src/scripts/index_catalog.py --rebuild
```

Если OCR временно не нужен или не хватает памяти:

```bash
uv run python src/scripts/index_catalog.py --filenames-only
```

Скрипты используют `Slug` каталога даже тогда, когда имя файла изображения
не совпадает со slug. Для записи без эталонной фотографии создаётся OCR-точка
по профилю каталога. Поле `Название фото` — это имя исходного файла из
каталога, по которому индексатор связывает запись с файлом в `data/images/`;
оно не является именем файла, который загружает пользователь в API.

## API

Основной evaluator-контракт для скрипта кейсодержателя принимает поле `image`
на endpoint `/v1/eval/predict` и возвращает один плоский JSON-объект:

```bash
curl -F "image=@photo.jpg" http://localhost:8000/v1/eval/predict
```

```json
{"slug":"wine-slug"}
```

Endpoint `/search` с полем `photo` сохраняется как совместимый локальный
контракт для старых клиентов.

Для пользовательского интерфейса используется подробный контракт:

```bash
curl -F "photo=@photo.jpg" http://localhost:8000/search/details
```

Он возвращает `found`, список кандидатов, визуальный `margin` и число
подтверждённых OCR-совпадений. При слабом совпадении сервис возвращает
кандидатов как возможные аналоги, но ставит `found=false` и не выдаёт их за
точную карточку. Если кандидатов нет, evaluator-контракт безопасно возвращает
`{"slug":null}`.

Кандидат с известным `slug` дополнительно обогащается полем `card` из
PostgreSQL. В карточке доступны название, винодельня, регион, сорт, категория,
цвет, описание, рейтинг Роскачества, рекомендация к подаче и ссылка на
страницу вина. Новые поля nullable: если рекомендации к подаче нет в
JSON-каталоге, API возвращает `null`, а UI не создаёт этот блок и не подставляет
выдуманное значение.

После точного поиска UI предлагает `GET /pairing/{slug}`. Endpoint
детерминированно подбирает блюдо по стилю вина или возвращает рекомендацию из
карточки каталога; внешние API не используются.

## Основные настройки

Все настройки имеют префикс `APP_` и могут быть заданы в `.env`:

- относительные пути (`APP_CATALOG_PATH`, `APP_LINKS_PATH`, `APP_IMAGES_PATH`,
  `APP_YOLO_MODEL_PATH`) разрешаются относительно корня приложения, а не
  текущего каталога запуска; абсолютные пути тоже поддерживаются;
- `APP_CATALOG_PATH` — путь к JSON-файлу только для импорта карточек;
- `APP_LINKS_PATH` — путь к JSON-файлу ссылок только для импорта;
- `APP_IMAGES_PATH` — каталог изображений для индексаторов;
- `APP_YOLO_MODEL_PATH` — путь к весам YOLO;
- `APP_DATABASE_URL` — SQLAlchemy URL PostgreSQL;
- `APP_CATALOG_REIMPORT=true` — принудительно заново импортировать JSON при
  запуске контейнера;
- `APP_SIGLIP_REVISION` и `APP_TEXT_MODEL_REVISION` — зафиксированные commit
  SHA моделей Hugging Face для воспроизводимой загрузки моделей;
- `APP_MAX_UPLOAD_SIZE_BYTES` — максимальный размер входного изображения;
- `APP_EMBEDDING_DEVICE=auto|cuda|mps|cpu`;
- `APP_YOLO_DEVICE=auto|0|cpu`;
- `APP_OCR_DEVICE=auto|gpu:0|cpu`;
- `APP_RETRIEVAL_VISUAL_SCORE_THRESHOLD` — минимальный визуальный score для
  принятия top-1;
- `APP_RETRIEVAL_VISUAL_STRONG_SCORE_THRESHOLD` — score, при котором сильный
  визуальный top-1 может быть принят при небольшом отрыве от второго кандидата;
- `APP_RETRIEVAL_VISUAL_MARGIN_THRESHOLD` — минимальный отрыв от второго
  визуального кандидата;
- `APP_RETRIEVAL_OCR_VISUAL_SCORE_THRESHOLD` — минимальный score визуального
  top-1 при подтверждении по OCR;
- `APP_OCR_ENABLED` — включение дополнительного OCR-канала.

Решение `found` принимается явными правилами: визуальный top-1 должен пройти
порог score и отрыва либо быть выше сильного score-порога; подтверждённое
лексическое OCR-совпадение может подтвердить визуальный top-1 или отдельный
OCR-кандидат без визуального результата.

## Ограничения

- GPU-образ рассчитан на NVIDIA GPU с драйвером, совместимым с CUDA 12.6; он
  не привязан к RTX 3050, но не является универсальным образом для CPU/AMD;
- если при импорте каталога отсутствуют рейтинг или рекомендация к подаче,
  карточка сохраняет `null`; блок рекомендации к подаче в UI не отображается;
- одинаковые значения `Название фото` логируются при индексации; для связи
  изображения используется первая запись, а остальные остаются доступными как
  catalog-only карточки.
